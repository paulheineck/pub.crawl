# Pub.Crawl – browser version

The same Pub.Crawl, but as a web page: nothing to install, nothing to
download. Open the page, pick journals from the catalog, start swiping.

Everything is stored **in your browser** (IndexedDB) on that device: feeds,
reading list, notes, likes/skips. There is no account and no backend database.
Use *Settings → export state as JSON* to back up or move to another device;
the format is compatible with the local Python version in both directions.

## How it differs from the local version

| | local (Flask) | browser |
|---|---|---|
| Install | Python + `start` script | none – open a URL |
| Data | `dashboard.db` on disk | browser storage of that device |
| Feeds | fetched by Python | fetched through a small proxy (`/proxy`, see below) |
| Abstracts, authors, DOIs | CrossRef / OpenAlex | same, fetched directly from the browser |
| Features | — | identical: deck, reading list, notes, relevance ranking, RIS, OPML, Unpaywall |

## Why a proxy?

Browsers block pages from reading RSS feeds on other domains (CORS), and
journal publishers don't send the header that would allow it. So the app is
deployed as a Cloudflare Worker ([`proxy/worker.js`](proxy/worker.js)) that
serves the static files *and* answers `/proxy?url=…` by fetching the feed.
It stores nothing apart from a 10-minute edge cache. CrossRef, OpenAlex and
Unpaywall allow browser requests directly.

## Running it locally

```bash
python web/dev_server.py
```

Then open <http://localhost:8765>. The dev server serves `web/` and plays the
proxy role under `/proxy?url=…`, so no Cloudflare account is needed for testing.

## Deploying on Cloudflare (free)

1. Cloudflare dashboard → *Workers & Pages* → *Create* → *Import a repository*
   → pick this GitHub repo.
2. Build settings:
   - **Root directory:** `web`
   - **Build command:** *(empty)*
   - **Deploy command:** `npx wrangler deploy`
3. Deploy. Cloudflare redeploys on every push to the production branch
   (Settings → Build → Branch control).

The app is then live at `https://<worker-name>.<account>.workers.dev`.
Configuration lives in [`wrangler.toml`](wrangler.toml); [`.assetsignore`](.assetsignore)
keeps the Python helpers, the worker source and docs from being served.

If you edit `journals.yaml`, regenerate the catalog with
`python web/build_catalog.py` and commit `web/journals.json`.

## Files

```
web/
  index.html, style.css     page + styles
  hilfe.html                user guide (German)
  impressum.html            legal notice + privacy policy (fill in your details!)
  vendor/pico.min.css       Pico.css 2.0.6, self-hosted (no third-party CDN)
  js/app.js                 views, deck, reading list, settings
  js/feeds.js               fetch + parse RSS/Atom, filters, IDs
  js/meta.js                CrossRef / OpenAlex / Unpaywall, RIS
  js/relevance.js           "for me" ranking, streak
  js/store.js               IndexedDB storage
  js/config.js              proxy address and constants
  journals.json             catalog, generated by build_catalog.py
  proxy/worker.js           Cloudflare Worker: feed proxy
  wrangler.toml             Cloudflare config (static files + worker)
  dev_server.py             local test server incl. proxy
```
